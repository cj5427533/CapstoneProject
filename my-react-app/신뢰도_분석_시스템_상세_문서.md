## 1. 개요

### 1.1 시스템 목적

여기몰까 플랫폼은 두 가지 핵심 신뢰도 분석 시스템을 제공합니다:

1. **리뷰 신뢰도 분석**: 쇼핑몰에 등록된 리뷰/신고/후기 텍스트의 신뢰도를 AI 기반으로 분석

- **AI 기반 분석**: Claude 3.5 Sonnet을 활용한 자연어 처리

- **실시간 분석**: 사용자 요청 시 즉시 분석 수행
- **캐싱 시스템**: 분석 결과 캐싱으로 성능 최적화
- **배치 처리**: 대량 리뷰 분석 시 효율적인 배치 처리

## 2. 리뷰 신뢰도 분석 시스템

### 2.1 개요

리뷰 신뢰도 분석 시스템은 쇼핑몰에 등록된 리뷰, 신고, 후기 텍스트를 AI가 분석하여 각 리뷰의 신뢰도를 평가하는 시스템입니다.

**분석 대상**:
- `shop_ratings` 테이블의 리뷰 (comment가 있는 리뷰만)
- `shop_reports` 테이블의 신고 (description이 있는 신고만)
- 부모/자식 쇼핑몰 관계를 고려하여 관련된 모든 리뷰 수집

**사용 기술**:
- **AI 모델**: Claude 3.5 Sonnet (OpenRouter API)
- **배치 크기**: 15개씩 묶어서 처리
- **캐시 유효 시간**: 5분

### 2.2 판별 기준 (AI 분석 기준)

AI 모델이 리뷰를 분석할 때 다음 6가지 기준을 종합적으로 고려합니다:

#### 2.2.1 균형 없는 평가
- **기준**: 너무 좋은 표현만 있거나 너무 나쁜 표현만 있는 경우
- **예시**: "최고", "완벽", "최악", "사기" 등 극단적 표현만 반복
- **의심도**: 극단적 표현이 2개 이상 사용되면 의심

#### 2.2.2 동일 패턴 리뷰
- **기준**: 비슷한 문체나 비슷한 내용의 리뷰가 다수 존재
- **예시**: 
  - "정말 좋아요! 배송도 빠르고 상품도 만족합니다."
  - "정말 좋아요! 배송도 빠르고 상품도 만족합니다."
  - "정말 좋아요! 배송도 빠르고 상품도 만족합니다."
- **의심도**: 동일하거나 매우 유사한 리뷰가 3개 이상이면 의심

#### 2.2.3 시간대 편중
- **기준**: 짧은 시간 내에 다수의 리뷰가 작성됨
- **예시**: 5분 내에 3개 이상의 리뷰가 연속으로 작성됨
- **의심도**: 5분 내 3개 이상이면 의심

#### 2.2.4 과도한 극단 표현 반복
- **기준**: "최고", "완벽", "최악", "사기" 등 극단적 표현이 반복적으로 사용됨
- **예시**: "정말 최고입니다! 완벽한 상품이에요! 최고의 쇼핑몰입니다!"
- **의심도**: 극단적 표현이 2개 이상 사용되면 의심

#### 2.2.5 구체적인 경험 부족
- **기준**: 모호한 표현이나 일반적인 문구만 사용, 구체적인 경험을 언급하지 않음
- **예시**: 
  - "좋아요" (구체적 경험 없음)
  - "배송이 빠르고 상품이 좋아요" (구체적 경험 있음)
- **의심도**: 모호한 표현만 있고 구체적 경험이 없으면 의심

#### 2.2.6 비정상적인 평점 분포
- **기준**: 90% 이상이 5점 리뷰인 경우
- **예시**: 전체 리뷰 100개 중 95개가 5점
- **의심도**: 5점 리뷰 비율이 90% 이상이면 의심

## 3. 쇼핑몰 신뢰도 분석 시스템

### 3.1 개요

쇼핑몰 신뢰도 분석 시스템은 쇼핑몰 URL의 기술적 특성을 ML 모델로 분석하여 피싱 가능성을 평가하는 시스템입니다.

**분석 대상**:
- 쇼핑몰 URL (정규화된 URL)
- URL의 9가지 특징 추출
- ML 모델(Random Forest)을 통한 예측

**사용 기술**:
- **ML 모델**: Random Forest (Python scikit-learn)
- **학습 데이터**: 실제 피싱 사이트 데이터
- **특징 수**: 9가지 URL 특징

### 3.2 판별 기준 (ML 모델 특징)

ML 모델이 분석하는 9가지 URL 특징:

#### 3.2.1 URL 길이
- **기준**: URL 전체 길이
- **의심도**: URL이 너무 길면 의심 (일반적으로 100자 이상)
- **예시**: 
  - 정상: `https://example.com`
  - 의심: `https://secure-verify-account-login-confirm-payment.example.com/verify/account/secure/login`

#### 3.2.2 하이픈 개수
- **기준**: URL에 포함된 하이픈(`-`) 개수
- **의심도**: 하이픈이 많을수록 의심 (일반적으로 5개 이상)
- **예시**:
  - 정상: `https://example.com`
  - 의심: `https://secure-verify-account-login-confirm-payment.example.com`

#### 3.2.3 서브도메인 깊이
- **기준**: 서브도메인 레벨 수
- **의심도**: 서브도메인이 많을수록 의심 (일반적으로 3단계 이상)
- **예시**:
  - 정상: `https://www.example.com`
  - 의심: `https://secure.verify.account.example.com`

#### 3.2.4 도메인 확장자 (TLD)
- **기준**: 도메인 확장자 (.com, .net, .tk 등)
- **의심도**: 의심스러운 TLD 사용 시 의심
- **의심 TLD**: `.tk`, `.ml`, `.ga`, `.cf`, `.click`, `.download`
- **예시**:
  - 정상: `https://example.com`
  - 의심: `https://example.tk`

#### 3.2.5 IP 주소 사용 여부
- **기준**: URL에 IP 주소가 직접 사용되는지 여부
- **의심도**: IP 주소 직접 사용 시 의심
- **예시**:
  - 정상: `https://example.com`
  - 의심: `https://192.168.1.1`

#### 3.2.6 URL 단축 서비스 사용 여부
- **기준**: bit.ly, tinyurl.com 등 URL 단축 서비스 사용 여부
- **의심도**: URL 단축 서비스 사용 시 의심
- **예시**:
  - 정상: `https://example.com`
  - 의심: `https://bit.ly/abc123`

#### 3.2.7 HTTPS 사용 여부
- **기준**: HTTPS 프로토콜 사용 여부
- **의심도**: HTTPS 미사용 시 의심
- **예시**:
  - 정상: `https://example.com`
  - 의심: `http://example.com`

#### 3.2.8 의심 키워드 포함 여부
- **기준**: URL에 피싱에 자주 사용되는 키워드 포함 여부
- **의심 키워드**: `login`, `verify`, `confirm`, `account`, `discount`, `free`, `secure`, `payment` 등
- **의심도**: 의심 키워드가 많을수록 의심 (일반적으로 3개 이상)
- **예시**:
  - 정상: `https://example.com`
  - 의심: `https://secure-verify-account-login.example.com`

#### 3.2.9 @ 기호 포함 여부
- **기준**: URL에 @ 기호 포함 여부
- **의심도**: @ 기호 포함 시 의심
- **예시**:
  - 정상: `https://example.com`
  - 의심: `https://user@example.com`

### 3.3 작동 원리

#### 3.3.1 URL 정규화 단계

```javascript
function normalizeUrl(url) {
  // 1. 공백 제거 및 정리
  url = url.trim().replace(/\s+/g, '');
  
  // 2. 프로토콜이 없으면 https:// 추가
  if (!url.match(/^https?:\/\//i)) {
    url = 'https://' + url;
  }
  
  // 3. URL 객체로 파싱
  const urlObj = new URL(url);
  
  // 4. 호스트명 소문자화 및 www. 제거
  let hostname = urlObj.hostname.toLowerCase();
  if (hostname.startsWith('www.')) {
    hostname = hostname.substring(4);
  }
  
  // 5. 모바일 서브도메인 제거 (m., mobile. 등)
  const mobilePrefixes = ['m.', 'mobile.', 'm2.', 'm1.', 'wap.'];
  for (const prefix of mobilePrefixes) {
    if (hostname.startsWith(prefix)) {
      hostname = hostname.substring(prefix.length);
      break;
    }
  }
  
  // 6. 쿼리스트링과 앵커 제거
  return hostname + urlObj.pathname;
}
```

```python
        'subdomain_depth': len([x for x in url.split('.') if x]) - 2,  # TLD 제외
        'suspicious_tld': 1 if any(tld in url for tld in ['.tk', '.ml', '.ga', '.cf', '.click', '.download']) else 0,
        'ip_address': 1 if re.match(r'^\d+\.\d+\.\d+\.\d+', url) else 0,
        'shortening_service': 1 if any(service in url for service in ['bit.ly', 'tinyurl.com', 'goo.gl']) else 0,
        'https': 1 if url.startswith('https://') else 0,
        'suspicious_keywords': sum(1 for keyword in ['login', 'verify', 'confirm', 'account', 'discount', 'free', 'secure', 'payment'] if keyword in url.lower()),
        'at_symbol': 1 if '@' in url else 0
    }
    return features
```

#### 3.3.3 ML 모델 예측 단계

Python ML 모델(Random Forest)이 특징을 기반으로 예측:

```python
import pickle
import json
import sys

# 학습된 모델 로드
with open('best_model.pkl', 'rb') as f:
    model = pickle.load(f)

# URL 리스트 읽기 (stdin에서 JSON으로 받음)
urls = json.loads(sys.stdin.read())

# 각 URL에 대해 예측 수행
results = []
for url in urls:
    features = extract_features(url)
    feature_vector = [
        features['url_length'],
        features['hyphen_count'],
        features['subdomain_depth'],
        features['suspicious_tld'],
        features['ip_address'],
        features['shortening_service'],
        features['https'],
        features['suspicious_keywords'],
        features['at_symbol']
    ]
    
    # 예측 수행
    prediction = model.predict([feature_vector])[0]  # 0: SAFE, 1: PHISHING
    probability = model.predict_proba([feature_vector])[0]
    confidence = max(probability)  # 예측 확률
    
    results.append({
        'url': url,
        'label': int(prediction),
        'confidence': float(confidence)
    })

# 결과 출력 (stdout으로 JSON 반환)
print(json.dumps(results))
```

#### 3.3.4 신뢰도 점수 계산 단계

ML 예측 결과를 0~100점 신뢰도 점수로 변환:

```javascript
function computeMlTrustScore(label, confidence) {
  // confidence 값 유효성 검사
  if (typeof confidence !== 'number' || isNaN(confidence) || confidence < 0 || confidence > 1) {
    confidence = 0.5;
  }
  
  // confidence를 0.1~0.99 범위로 정규화
  const normalizedConfidence = Math.max(0.1, Math.min(0.99, confidence));
  
  let trustScore;
  if (label === 0) {
    // SAFE: confidence가 높을수록 높은 trustScore
    trustScore = 100 * normalizedConfidence;
  } else if (label === 1) {
    // PHISHING: confidence가 높을수록 낮은 trustScore
    trustScore = 100 * (1 - normalizedConfidence);
  } else {
    // 기본값
    trustScore = 50;
  }
  
  // 0.1 단위로 반올림
  if (trustScore >= 100.0) {
    return 100;
  }
  return Math.max(0, Math.min(99.9, Math.round(trustScore * 10) / 10));
}
```

**점수 변환 예시**:
- `label=0, confidence=0.95` → `trustScore = 100 * 0.95 = 95.0점` (안전)
- `label=0, confidence=0.50` → `trustScore = 100 * 0.50 = 50.0점` (중간)
- `label=1, confidence=0.95` → `trustScore = 100 * (1 - 0.95) = 5.0점` (위험)
- `label=1, confidence=0.50` → `trustScore = 100 * (1 - 0.50) = 50.0점` (중간)

#### 3.3.5 최종 신뢰도 점수 계산 단계

리뷰 신뢰도 분석 결과와 ML 예측 결과를 종합하여 최종 신뢰도 점수 계산:

```javascript
// 1. 리뷰 위험도 계산 (리뷰 신뢰도 분석 결과 기반)
// overallTrustScore (0~1, 1에 가까울수록 신뢰도 높음)를 reviewRisk (0~1, 1에 가까울수록 위험도 높음)로 변환
const reviewRisk = 1 - analysisResult.overallTrustScore;

// 2. 기술적 위험도 계산 (ML 예측 결과 기반)
// ML 예측 결과를 techRisk (0~1, 1에 가까울수록 위험도 높음)로 변환
const techRisk = mlLabel === 1 
  ? mlConfidence  // PHISHING: confidence가 높을수록 위험도 높음
  : 1 - mlConfidence;  // SAFE: confidence가 높을수록 위험도 낮음

// 3. 신고 패널티 계산
const reportPenalty = await calculateReportPenalty(shopId);
// 신고 건수에 따른 패널티:
// 0건: 0점
// 1건: 2점
// 2건: 5점
// 3~4건: 8점
// 5~7건: 12점
// 8건 이상: 15점

// 4. 최종 신뢰도 점수 계산
// 점수 계산: 100 - (techRisk * 75) - (reviewRisk * 10) - reportPenalty
const finalTrust = Math.max(
  0,
  Math.min(
    100,
    100 - techRisk * 75 - reviewRisk * 10 - reportPenalty
  )
);

// 5. 신뢰도 등급 결정
let trustGrade;
if (finalTrust >= 90) {
  trustGrade = 'VERY_HIGH';  // 매우안전(파랑)
} else if (finalTrust >= 70) {
  trustGrade = 'HIGH';       // 안전(초록)
} else if (finalTrust >= 40) {
  trustGrade = 'CAUTION';    // 주의(노랑)
} else {
  trustGrade = 'LOW';        // 의심(주황) - 0~39
}
```

**가중치 설명**:
- **techRisk (75점)**: 기술적 위험도가 가장 큰 영향을 미침 (ML 모델 예측)
- **reviewRisk (10점)**: 리뷰 위험도는 보조적 역할
- **reportPenalty (최대 15점)**: 신고 건수에 따른 패널티

**점수 계산 예시**:
- `techRisk=0.1, reviewRisk=0.2, reportPenalty=0` → `finalTrust = 100 - 7.5 - 2 - 0 = 90.5점` (매우안전)
- `techRisk=0.5, reviewRisk=0.3, reportPenalty=5` → `finalTrust = 100 - 37.5 - 3 - 5 = 54.5점` (주의)
- `techRisk=0.9, reviewRisk=0.5, reportPenalty=15` → `finalTrust = 100 - 67.5 - 5 - 15 = 12.5점` (의심)
